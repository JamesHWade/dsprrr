dsprrr×deputy

Two packages, one lifecycle. dsprrr defines, evaluates, and optimizes LLM skills. deputy deploys them inside governed agents. Both are already built on ellmer — the integration is closer than you think.

Use ellmer as the interoperability contract. Let dsprrr produce optimized, typed LLM skills. Let deputy deploy those skills inside governed agents. Let each package remain useful independently.

System design

ellmer as the bridge

Both packages already speak ellmer. Tools, types, chat objects, and structured output schemas flow between the layers without either package importing the other.

①

Module → ellmer tool → deputy

An optimized dsprrr module becomes an ellmer tool, registered in a deputy agent. Permissions and annotations govern its use at runtime.

②

deputy tools → react module

deputy tool bundles are ellmer tools. Pass them directly to a dsprrr react module to evaluate and optimize tool-using behavior.

③

deputy agent → dsprrr module

A full deputy Agent is wrapped as a dsprrr module via agent_as_module(). Evaluate it on datasets; permissions are preserved.

④

Signature → JSON schema → output_format

Define the output contract once in a dsprrr signature. Convert to a deputy output format for structured agent responses.

Integrated workflows

Each direction solves a real problem. Pick the one that matches your current pain, or compose them for the full lifecycle.

Deploy an optimized skill as a deputy tool

Stop embedding one-off prompts in agent system prompts. Define the skill in dsprrr, measure it, improve it, then deploy it as a typed tool inside a deputy agent.

The optimized module runs under deputy permissions and hooks. The agent can call it, inspect its output, and recover from failures — all within the permission envelope you define.

  • Define the skill with a dsprrr signature
  • Evaluate baseline accuracy on labeled examples
  • Optimize with LabeledFewShot or MIPROv2
  • Convert via tool_dsprrr_module() with read-only annotations
  • Deploy inside a permissioned deputy agent
as_ellmer_tool() tool_dsprrr_module() tool_annotations()
R 
# 1. Define the skill
sig <- dsprrr::signature(
  "ticket -> category: enum('bug','billing','feature','other'),
             urgency: enum('low','medium','high')"
)
triage <- dsprrr::module(
  sig,
  chat = ellmer::chat("openai/gpt-4o-mini")
)

# 2. Evaluate baseline
score_before <- dsprrr::evaluate(
  triage, train_tickets,
  metric = metric_exact_match()
)

# 3. Optimize with few-shot examples
triage_opt <- dsprrr::compile(
  dsprrr::LabeledFewShot(k = 4),
  triage,
  trainset = train_tickets
)

# 4. Convert to a deputy tool (read-only by default)
triage_tool <- deputy::tool_dsprrr_module(
  triage_opt,
  name = "triage_ticket",
  description = "Classify a support ticket."
)

# 5. Deploy in a permissioned agent
agent <- deputy::Agent$new(
  chat = ellmer::chat("openai/gpt-4o"),
  tools = list(triage_tool),
  permissions = deputy::permissions_readonly()
)

result <- agent$run_sync(
  "Triage: customer cannot access invoice history."
)
cat(result$response)

Use deputy tools inside a dsprrr react module

deputy tools are ellmer tools. They can be passed directly into a dsprrr react module today — no adapter needed.

This lets you benchmark and optimize tool-using behavior before deployment. Which tools does the model overuse? Which prompts lead to fewer unnecessary calls?

  • Grab a deputy tool preset or build a custom bundle
  • Pass tools to a dsprrr react module
  • Run and trace tool-using behavior
  • Evaluate on a task dataset
  • Note: deputy permissions are not active outside a deputy-managed runtime
tools_preset() module(type = "react") trace_summary()
R 
# deputy tools are ellmer tools — pass them directly
mod <- dsprrr::module(
  dsprrr::signature("question -> answer"),
  type = "react",
  tools = deputy::tools_preset("minimal"),
  chat = ellmer::chat("openai/gpt-4o")
)

# Run and inspect traces
result <- dsprrr::run(
  mod,
  question = "What exported functions does this package have?"
)

# Trace shows tool calls, reasoning steps, outputs
mod$trace_summary()

# Evaluate tool-use quality across many questions
eval_results <- dsprrr::evaluate(
  mod,
  data = file_qa_dataset,
  metric = metric_exact_match()
)

# Note the caveat:
# deputy permissions are enforced by the deputy runtime.
# Tools used here run outside that runtime — no permission checks.
# For governed execution, run via a deputy Agent instead.

Evaluate a full deputy agent with dsprrr

Wrap a complete deputy Agent as a dsprrr module. Now you can evaluate it on a labeled dataset just like any other module — tracking correctness, cost, latency, and stop reasons across runs.

By default the agent is cloned per evaluation row, so turn history from row 1 cannot contaminate row 2. Deputy permissions are fully preserved inside the wrapper.

  • Create a deputy agent with tools and permissions
  • Wrap via agent_as_module() with a dsprrr signature
  • Evaluate against a labeled task dataset
  • Inspect stop_reason to separate quality failures from policy failures
  • Compare two agent configs before deploying either
agent_as_module() evaluate() module_fn()
R 
eval_set <- tibble::tibble(
  task     = c("Which files define exports?", "Are there tests?"),
  expected = c("R/", "tests/")
)

agent <- deputy::Agent$new(
  chat = ellmer::chat("openai/gpt-4o-mini"),
  tools = deputy::tools_preset("minimal"),
  permissions = deputy::permissions_readonly()
)

# Wrap as a dsprrr module (agent cloned per row by default)
agent_mod <- deputy::agent_as_module(
  agent,
  signature = dsprrr::signature("task -> answer"),
  max_turns = 8,
  clone_agent = TRUE     # prevents turn-history contamination
)

results <- dsprrr::evaluate(
  agent_mod,
  data = eval_set,
  metric = function(example, prediction) {
    grepl(example$expected, prediction$answer, fixed = TRUE)
  }
)

# Each result includes compact deputy metadata:
# stop_reason, duration, cost, n_turns, n_events
results$metadata[[1]]$deputy

One output contract, two systems

Define structured output once in a dsprrr signature. Convert it to a deputy output format for use in agent calls. The same schema validates both the optimized module and the deployed agent.

No more maintaining two copies of the same JSON schema. The dsprrr signature is the schema — output_type is already an ellmer type object; conversion is straightforward traversal.

  • Define signature with typed multi-field output
  • Convert via output_format_from_signature()
  • Run agent with structured output requested
  • Read parsed output from result$structured_output$parsed
signature_to_json_schema() output_format_from_signature()
R 
# Define output contract once
review_sig <- dsprrr::signature(
  "document -> summary,
               risks: array(string),
               confidence: number",
  instructions = "Return structured findings only."
)

# Use in dsprrr module (skill development)
review_mod <- dsprrr::module(review_sig)
# ... evaluate, optimize ...

# Use same schema in deputy agent call
output_format <- deputy::output_format_from_signature(review_sig)
# => list(type = "json_schema",
#         schema = list(type = "object",
#                       properties = list(
#                         summary = list(type = "string"),
#                         risks   = list(type = "array",
#                                        items = list(type = "string")),
#                         confidence = list(type = "number")),
#                       required = c("summary","risks","confidence"),
#                       additionalProperties = FALSE))

result <- agent$run_sync(
  "Review this technical note: ...",
  output_format = output_format
)

# Parsed R list — not raw JSON
result$structured_output$parsed
#> $summary      "The study shows..."
#> $risks        c("Small sample size", "No control group")
#> $confidence   0.74

Roadmap

Six implementation phases

Ordered by dependency. Each phase unlocks the next. Phases 1–3 can begin immediately with the current codebase.

P1
Make existing interop explicit Documentation

No API changes. Formalize what already nearly works: deputy tools in dsprrr react modules, dsprrr modules as ellmer tools in deputy agents. Add minimal regression tests.

vignette: deputy-tools.Rmd tests: prevent regressions permission caveat documented
→ Unblocks: teams can start using both packages together today
P2
Harden dsprrr::as_ellmer_tool() Highest priority

Add annotations, output, copy, and error arguments. Stable JSON serialization. Recoverable error behavior. Deep copy via module$copy(deep = TRUE) (already implemented in Module base class).

annotations passthrough output = "json"|"text"|"auto" copy = "deep"|"none" error = "reject"|"abort"|"return" test-ellmer-tool-adapter.R
→ Unblocks: Phase 3 (deputy wrapper)
P3
Add deputy::tool_dsprrr_module() Deputy

Thin convenience wrapper over as_ellmer_tool() with deputy-safe defaults: copy = "deep", read-only annotations. dsprrr in Suggests only — no hard import.

R/tools-dsprrr.R read-only default annotations permission mode tests vignette: dsprrr-integration.Rmd
→ Unblocks: clean UX for direction ①
P4
Add dsprrr::module_fn() dsprrr

New FnModule R6 class inheriting from Module. Override only forward(). Gets run(), evaluate(), and copy() for free via inheritance. Optimizers error clearly on FnModule in v1.

R/module-fn.R (FnModule R6) module_fn() factory run() + evaluate() work optimizer guard with clear error
→ Unblocks: Phase 5 (agent_as_module)
P5
Add deputy::agent_as_module() Deputy

Wrap a deputy Agent as a dsprrr module via module_fn(). Clones agent per evaluation row by default (clone_agent = TRUE). Reads result$structured_output$parsed. Preserves stop_reason for policy-vs-quality failure diagnosis.

R/agent-dsprrr.R clone_agent = TRUE default structured_output$parsed extraction stop_reason in metadata vignette: agent-evaluation.Rmd
→ Unblocks: direction ③ (full agent evaluation)
P6
Signature-to-schema bridge Both

Add dsprrr::signature_to_json_schema() (traverse output_type ellmer types) and deputy::output_format_from_signature() (thin wrapper). additionalProperties = FALSE. Warn on unsupported types, never fail silently.

R/signature-json-schema.R R/output-format-dsprrr.R all ellmer types covered vignette: signature-output-format.Rmd
→ Unblocks: direction ④ (shared output contracts)

Definition of done

Ready when all ten ship

The integration is complete for v1 when these ten criteria are verifiably true.

A dsprrr module converts to a deputy tool with annotations, stable output, and recoverable errors
A deputy tool bundle is usable inside a dsprrr react module, with permission caveats documented
A full deputy agent wraps as a dsprrr module, is evaluated on datasets, and clones per row
A dsprrr signature converts to a deputy structured-output format for all common types
Tests cover all four directions, permission behavior, agent cloning, and metadata capture
Five vignettes demonstrate all prioritized workflows (deputy-tools, dsprrr-integration, agent-evaluation, signature-output-format, research-analyst)
No circular dependencies: dsprrr does not import deputy; deputy Suggests dsprrr only
deputy permissions are preserved exactly when wrapping agents; not active outside deputy runtime
stop_reason distinguishes quality failures from policy failures in agent evaluation metadata
The flagship research analyst vignette demonstrates the integrated lifecycle end-to-end
